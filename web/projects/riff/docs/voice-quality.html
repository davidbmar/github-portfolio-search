Voice Quality Playbook

TL;DR: Voice agent defects hide within transient audio timings and FSM race conditions that appear clean in standard text transcripts. By combining automated nightly evaluations in quality.db with a faithful real-audio reproducing harness (scripts/voice_case.py), we enforce a strict shift-left engineering cycle. Timing races and terminal glitches are caught early by running deterministic simulations (tests/test_live_confirm_gates_all_flows.py) in our CI pipeline, ensuring FSM transitions and conversational gates operate reliably across all flows.

1. The voice-quality problem class

Standard text-based evaluations are blind to timing. A conversation log may show a clean sequence of turns ("read_back → yes → complete"), but hide a catastrophic 50-second dead air gap or a 9-second silence. Under the hood, these issues are often caused by timing races where FSM guards fail to fire at turn boundaries.

Systemic voice bugs typically exhibit specific signatures:

  • "Are you still there?" — Callers ask this when the agent goes silent, indicating dead air from FSM stalls.
  • Loop score ≥ 4 or high turn counts with no completion, indicating the FSM is stuck.
  • Spurious denials/re-narrations — The agent repeats its summary or registers incorrect transitions due to unexpected caller utterances (e.g. saying "Thanks" at the end of a call).

2. The quality loop

To systematically eliminate these timing bugs, we follow a five-stage quality loop:

  1. Detect: Nightly reviews run at 01:30 (via scripts/nightly_review_cycle.sh) and fold metrics into quality.db.live_call_reviews.
  2. Reproduce: We turn real call anomalies into deterministic voice cases using scripts/voice_case.py. This harness connects to the real live WebSocket, plays audio via TTS (macOS say), and precisely controls caller reply timing relative to the agent's playback end.
  3. Prevent (Shift-Left): The reproducing voice case is codified into a fast simulation test or a build-time flow linter rule to prevent regression.
  4. Fix Systemically: Patch the shared transport or session layer once rather than editing dozens of flow YAML files.
  5. Document: File a backlog item (e.g. docs/project-memory/backlog/B-NNN-*.md) detailing the root cause and regression test.

3. The two-tier testing model

RIFF uses a two-tier testing pyramid to catch and prevent regressions before they reach production:

Tier Tooling / Files Characteristics Primary Target
Tier 1: Simulation (CI) test_live_confirm_gates_all_flows.py Deterministic mock client, runs in <1s in CI, zero API cost FSM transition walks, logic bugs, group record validators
Tier 2: Real-Audio (Harness) scripts/voice_case.py Faithful real-audio stream, controls VAD/silence, runs periodically Barge-in behavior, VAD, microphone gating, network packet timing

4. Three bugs, as worked examples

B-319 — Read-back confirmation stall (Fixed)

Symptom: After an order was read back, the agent went silent for ~50 seconds at the confirmation gate. Callers asked "Are you still there?", triggering a spurious denial when they finally spoke.
  • Root Cause: The live session in riff/live/session.py:1366 classified the agent's read-back as a model-only turn (no user text, no tools) and bypassed the FSM transition walk. The FSM was stuck in read_back until the caller's next turn forced an evaluation.
  • Fix Location: [riff/live/session.py](file:///Users/davidmar/src/riff/riff/live/session.py#L1359-L1365). Added a conditional walk (_advances_on_own_emission) if the current state expects a response_emitted transition: 
    _advances_on_own_emission = (
    bool(self.turn.assistant_text)
    and any(
        getattr(t, "when", "") == "response_emitted"
        for t in (self.session.state_def().transitions or ())
    )
)
  • Regression Test: test_b319_readback_advances_on_model_only_turn in [tests/test_live_transport.py](file:///Users/davidmar/src/riff/tests/test_live_transport.py#L274).

B-320 — Terminal close state re-narration (Fixed)

Symptom: At the terminal submit_ticket state, the caller said "Thanks" or "Goodbye" before hangup. Instead of closing, the agent re-read the entire closing summary twice.
  • Root Cause: Post-terminal caller input arrived before the carrier hung up the WebSocket, causing Gemini to re-generate from the terminal state prompt.
  • Fix Location: [riff/live/session.py](file:///Users/davidmar/src/riff/riff/live/session.py#L1369-L1377). Flagged delivery of terminal close state: 
    if (getattr(_sdef, "terminal", False)
        and getattr(_sdef, "speech_act", "") == "close"
        and self.turn.assistant_text):
    self._terminal_close_delivered = True
    We then check this flag inside should_suppress_model_output() in [session.py:741](file:///Users/davidmar/src/riff/riff/live/session.py#L741) to suppress any further model output.
  • Regression Test: test_b320_terminal_close_suppresses_post_close_renarration in [tests/test_live_confirm_gates_all_flows.py](file:///Users/davidmar/src/riff/tests/test_live_confirm_gates_all_flows.py#L104).

B-318 — Verification "yes" as passcode (Open)

Symptom: The verification state failed because the model submitted the caller's verbal confirmation "yes" as the numeric verification code.
  • Root Cause: Tool calls fired in the same model turn (sending then immediately verifying in the same second), reusing the verbal confirmation "yes" as the code parameter.
  • Proposed Fix: Separate the turns in the verification FSM, filter argument formats on tutorial_verify_caller_code to reject alphabetic inputs, and raise `verification_max_attempts` from 1 to 3 in the module.

5. The sellable example

To demonstrate a perfect implementation of these patterns, we built a canonical after-hours message-taking flow: flows/after_hours_answering.yaml. Designed as the "$1/hour night-shift worker", it forwards calls, takes a message, reads it back, and routes urgent requests.

Crucially, it uses the standard Collect Pattern and serves as a regression fixture. Both the response_emitted transition (B-319) and the terminal close (B-320) are declared cleanly:

  read_back:
    speech_act: confirm
    entry:
      line: "Let me read that back so I've got it right:"
    transitions:
      - to: await_confirmation
        when: response_emitted # B-319 gate

  complete:
    speech_act: close
    entry:
      line: "Perfect — I've got your message..."
    terminal: true # B-320 close

The FSM test suite parameterized checks auto-discover this file, ensuring that any future regression fails CI immediately on this reference flow.

6. Voice quality metrics

The nightly review cycle compiles live metrics directly into the live_call_reviews database table inside quality.db. Key telemetry points tracked per session include:

  • overall, efficiency, naturalness, error_recovery — LLM-graded rubrics.
  • loop_score — Maximum visits to any single state (objective indicator of loops).
  • wer — Word Error Rate of the Gemini transcript against local Whisper ground truth (currently averaging **19.3%**).
  • transcription_source — Traces whether transcription ran locally (e.g. local) or via remote fallback.
  • hallucination_flags — Alerts operators when slot tokens do not appear in the Whisper ground truth.

7. Audio simulation — the dreamer

Tier 2 now drives every flow with injected audio, end to end. A generic LLM caller (scripts/voice_case.py --mode converse) answers whatever the agent asks, so one harness drives any flow to a terminal state over the real audio path — no per-flow scripting.

  • Caller personas (--persona) — each stresses a failure mode: cooperative (baseline), confused (B-303 confirm loop), corrector (re-read path), terse (mis-hear / WER).
  • Timing variance (--reply-delay-ms) — from eager (0ms, trips races) to a polite 2500ms pause.
  • The dreamer (scripts/voice_dream.py) randomly samples (flow × persona × timing), drives with audio, Whisper-transcribes, and upserts every metric to quality.db. It is property-based testing for voice: the breaking combinations surface in the data, not in inspection.

Two protocol bugs the dreamer forced — both invisible to static checks, found only by placing the real call:

  1. Trailing silence. Gemini's VAD ends a turn on speech→silence; the harness stopped sending frames (absence ≠ silence), so turns never ended. Sending explicit zero-PCM silence after each utterance fixed it.
  2. static_done. 28 flows (62%) have a static greeting that advances on audio_done, fired only when the browser sends static_done. The synthetic client must send it too, or every one stalls at greeting.
Corpus findings (all surfaced by the dreamer):
  • Static-greeting stall (28 flows) — the harness never sent static_done. Fixed.
  • cal-provider tool-scoping leak — provider tools (schedule_event, propose_booking) reached every flow's model when the calendar provider was booted, so pizza mis-called schedule_event (“booked a haircut”). Fixed: get_tools_for_turn now scopes provider tools to each flow's declared allowed_tools — real booking flows keep them, order flows lose the footgun. (Evolved the B-050 surface-parity contract to “declared tools reach the LLM”.)
  • B-303 / B-300 — flows reach await_confirmation then stall: the half-duplex gate ate the caller's confirm because the harness replied while the agent's audio was still playing. Harness fixed (wait for playback); the product gate-tail policy is the open question.
Validation flow: flows/sweet_things_bakery.yaml exercises all three fixes by construction, and the deterministic suites auto-discover it — a regression of any fix fails CI on this flow too.
Summary: By maintaining this two-tier pipeline — deterministic FSM checks plus a randomized audio dreamer — RIFF moves timing-sensitive bugs from elusive live mysteries to data you can rank, fix, and regress.
