Calendar/Scheduler Simulator — Report & Findings

Date: 2026-07-02 Audience: Fable 5 (morning review) What: a deterministic simulator + ~120 permutation tests over the RIFF calendar/scheduler offer→book loop (scheduling_v1, as defined in flows/austin_plumbing.yaml), and the real bug the simulator caught.

1. Why this exists

The existing deterministic sim harness (tests/test_sim_harness.py) deliberately excludes the scheduling flows — "they use tool calls." So the calendar path — the most valuable, highest-risk booking logic — had no deterministic permutation coverage; it was only exercised by the flaky, LLM-driven eval. This work closes that gap.

2. The simulator (tests/scheduler_sim.py)

  • FakeCalendar — a scriptable fake schedule_event backend. It mirrors the exact session slots the real cal_provider adapter mirrors, because the FSM guards read those slots (codex-verified contract): _booked_event_id (booking_confirmed), _last_booking_error_kind=="slot_conflict" (slot_busy) / other (booking_failed), empty offered → _scheduling_offered_count==0 (no_openings), and the engine-written selected-slot trio (selected_slot_ready). It generates offers on whatever date the engine probes, so it is immune to which clock the runtime uses.
  • SchedulerSim — a no-LLM driver: loads the real production flow, enters scheduling_triage, and drives each turn through run_turn → maybe_handle_locked_choice_turn → the real offer engine (maybe_prefetch_offer_slots / maybe_book_selected_slot). Every turn asserts adapter.calls == [] — proving the deterministic path was exercised and the LLM was never touched. Fresh session per case; the fake is the only calendar.

Driver + contract were codex-reviewed and APPROVED before implementation.

4. Finding B-CAL-1 — the bug the simulator caught

Deterministic-path slot-conflict retry does not re-offer. On the run_turn/cascade path, a same-slot race at the booking write does not run prepare_slot_conflict_retry: the required-tool dispatch performs the book+confirm and leaves _scheduling_state == "ERROR" (∉ PRE_BOOK_STATES), so maybe_book_selected_slot skips at scheduling_offer.py:360-388 before its own conflict cleanup at scheduling_offer.py:529-533. The stale selection survives, scheduling_selected_slot_ready re-fires, and the caller is bounced back to scheduling_confirm_slot_hold on the same dead slot (verified: 3× then escalate) instead of being offered fresh times.

  • Blast radius: the deterministic / cascade path (text, sim). The live voice path is unaffected — it cleans up separately in session.py:2124/2248.
  • Severity: bounded (it escalates, never loops forever, never fabricates a booking — proven by test_slot_conflict_is_bounded_and_never_fabricates_booking), but poor recovery UX on the cascade path.
  • Status: captured as two xfail(strict) tests asserting the correct behavior (re-offer fresh slots). strict=True means they flip to a hard failure the moment the gap is fixed — so the fix can't land without removing the marker. Fix deferred to operator review because it touches booking code shared by the live + cascade paths (double-handling risk with session.py:2124).

Fix decision (deliberate): keep xfail(strict), defer the fix to operator + codex review. The correct patch is a conflict-cleanup at the top of maybe_book_selected_slot (when it is entered with _last_booking_error_kind == "slot_conflict" and no _booked_event_id, run prepare_slot_conflict_retry + walk_transitions + re-prefetch — mirroring the existing cleanup at 529-533). The reason it is NOT applied autonomously: that function is shared by the live and cascade paths, and the live session already runs its own prepare_slot_conflict_retry at session.py:2124/2248, so a naive early-cleanup risks double-handling (a double walk_transitions) on the live path. Landing it safely needs the live-path ordering validated against the full live-session + scheduling suites — an operator-reviewed change, not a 3am blind edit to core booking code. codex reproduced the bug during review; its patch recommendation timed out, so the fix is queued with full repro rather than guessed.

4b. Aggregate integration check (whole-repo)

Final full-suite run on main with all five of the session's commits integrated: 7,605 passed / 109 failed / 186 xfailed / 30 skipped / 5 errors (7:33). Versus the pre-work baseline (42dd6850: 7,467 passed / 110 failed / 183 xfailed), the net effect of everything landed this session is +138 passing, −1 failing (a flaky audio-pacing timing test), +3 xfailed (the B-CAL-1 strict guards). None of the new test files appear in the failure set; every remaining failure/error is pre-existing (unrelated modules: editor_preview, live_models, complex_flows, sim_harness, dashscope, ops_shell, and pre-existing scheduling flow-schema drift). Per-slice isolation was also run for the shadow work (zero new failures attributable). Method note: run with -p no:faulthandler — a rare native-lib (torch/sentencepiece) transient can otherwise dump on an unrelated test; re-runs are clean.

5. One-line status

The calendar path now has deterministic permutation coverage it never had; 116 cases pass, and the simulator earned its keep on day one by catching a real conflict-retry gap the LLM eval would have masked.
