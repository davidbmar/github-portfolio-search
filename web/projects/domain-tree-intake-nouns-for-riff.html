Domain Tree Intake Nouns for riff

A precursor library that validates domain-specific JSON trees and compiles them into flat capability dictionaries for the riff intake system.

What it is

This project implements a three-pass pipeline for authoring business logic for service intakes. It generates draft domain trees via LLM, allows human pruning and locking, and compiles the locked tree structure into a flat schema compatible with the riff runtime. It handles branching logic, alias resolution guidance, and field phase ordering (problem, triage, identity).

Features

  • Validates Tree DSL against strict schema rules including depth and ID formats
  • Compiles hierarchical locked trees into flat capability dictionaries with branching conditions
  • Generates draft domain trees using LLM prompts for nouns and questions
  • Enforces conversation order phases: problem, triage, and identity
  • Provides alias resolution guidance for extractors to handle messy caller utterances

Quickstart

.venv/bin/pytest -q
.venv/bin/python scripts/build_dist.py
.venv/bin/python -m intake_trees.tree_gen --domain plumbing --persona "experienced residential plumber" --out trees/plumbing.draft.json

How it's built

Python standard library only. It uses argparse for CLI entry points, json for data handling, and re for validation. The core logic is split into tree_gen (LLM interaction), tree_schema (validation DSL), and tree_to_schema (compilation to flat dicts).

How to apply & reuse

Use this repo to define new service domains (e.g., plumbing, electrical). Run tree_gen to get a draft, manually edit the JSON to lock it, then run build_dist.py to produce the capability.json files. Copy these files into the riff repository's intake_schemas.py or load them directly.
