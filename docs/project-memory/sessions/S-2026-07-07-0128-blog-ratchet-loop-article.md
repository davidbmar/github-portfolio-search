# Session

Session-ID: S-2026-07-07-0128-blog-ratchet-loop-article
Title: Publish "Ratchet Loops" blog article + downloadable skills
Date: 2026-07-07
Author: Claude (David Mar's request)

## Goal

Publish a long-form article ("Ratchet Loops: Making an AI Agent Improve
Your System Without Letting It Grade Its Own Homework") as a page on
davidbmar.com, add a new "Blog" nav section, and ship two downloadable
Claude skill files (`ratchet-loop-starter.skill`, `ratchet-loop.skill`)
referenced from the article.

## Context

davidbmar.com is a static site (S3 + CloudFront), deployed via
`aws s3 sync` — either locally (`deploy.sh`) or via the `reindex.yml`
GitHub Actions workflow. The only prior long-form content convention is
`web/learn/` (self-contained HTML, inline CSS, no shared stylesheet,
generated by the portfolio-narrate skill). There was no prior "blog"
section and no existing downloads convention.

## Plan

1. Discover site conventions (deploy method, content page style, nav
   structure) before building anything.
2. Build `web/blog/` following the `web/learn/` visual pattern: a new
   `index.html` landing page plus the article itself.
3. Reconstruct the two Claude skills exactly from the provided source and
   zip each with its own folder as the zip root.
4. Add a single "Blog" link to the main nav in `web/index.html` only —
   not retroactively into every existing per-file nav bar, to avoid
   site-wide restructuring.
5. Commit on an isolated branch, then publish via the existing CI deploy
   path (local AWS creds are intentionally scoped without S3 write
   access — confirmed via a live `PutObject`/`DeleteObject` test, both
   denied).

## Changes Made

- Added `web/blog/index.html` — Blog landing/index page.
- Added `web/blog/2026.(JUL)07.06-RachetLoop.html` — the article, exact
  path as specified by the user (note: literal spelling "RachetLoop" as
  given, missing a "t" vs. "Ratchet" used everywhere else in the piece —
  flagged to the user, not silently corrected).
- Added `web/blog/downloads/ratchet-loop-starter.skill` and
  `ratchet-loop.skill` — zipped from scratch-built skill folders,
  reproduced verbatim from the provided SKILL SOURCE sections.
- Added a "Blog" link to the main site nav in `web/index.html`.
- Added `/blog/` and the article URL to `web/sitemap.xml`.
- Branched as `feat/blog-ratchet-loop` off the current HEAD (not
  `origin/main`, which is ~72 files / ~45k lines behind local HEAD and
  is missing the entire Droid feature) to avoid stranding the new page.

## Decisions Made

- Followed the `web/learn/` self-contained-HTML convention (inline
  `<style>`, no shared stylesheet, `site-bar` nav) rather than the SPA
  shell's `css/style.css`, since that's the site's established pattern
  for standalone long-form content.
- Did not add "Blog" to the `site-bar` nav duplicated across every
  existing Learn/Daily/Projects page — that would require touching many
  unrelated files, which the brief's guardrails explicitly rule out.
- Did not fabricate `ratchet-loop/references/examples.md`, even though
  the skill's own `SKILL.md` text references it — it wasn't part of the
  file tree or content given in the brief.

## Open Questions

- Is `RachetLoop` in the article's filename intentional, or should it be

  `gh workflow run reindex.yml` (or merging to `main` and waiting for
  the nightly cron), which is outside what this session executed.
