## Goal

Implement the L0 self-documenting-portfolio system from the approved spec
(`docs/superpowers/specs/2026-06-13-l0-project-docs-design.md`): a provider-agnostic
generator that emits one schema-validated structured record per GitHub repo, renders
each to a rich browser HTML page (Mermaid architecture + sequence diagrams, prose
sections, repo-hygiene TODO panel, embedded JSON island + JSON-LD), aggregates all
records to `web/data/projects.json`, and publishes via the existing S3/CloudFront
pipeline. Guinea pig: `generate_title_headline_hooks`.

## Context

Spec approved 2026-06-13 (commit 1e724c68). Implementation plan written via the
superpowers writing-plans skill:
`docs/superpowers/plans/2026-06-13-l0-project-docs.md` (11 tasks, TDD, bottom-up).
Executing via subagent-driven-development. User chose to work directly on `main`

## Plan

New `ghps.docsgen` subpackage: schema → hygiene → github_client extensions →
context → llm_client (DashScope/Anthropic via requests, zero new deps) → record_gen →
render → aggregate → orchestrator + `ghps gen-docs` CLI → guinea-pig run + deploy →
optional GitHub Action. Each task: fresh implementer subagent, then spec-compliance
review, then code-quality review.

## Changes Made

L0 generator pipeline implemented as a new `ghps.docsgen` subpackage (TDD,
subagent-driven, two-stage review per task). 21 commits on `main`
(`c138db52`..`4a23edda`), full suite 338 passed / 1 skipped (baseline was 260).

- `docsgen/schema.py` — hand-rolled `validate_record` (no jsonschema dep).
- `docsgen/hygiene.py` — `derive_todos` from branch/PR state.
- `github_client.py` — added `fetch_branches`, `compare_commits`, `fetch_open_prs`
  (paginated).
- `docsgen/context.py` — `RepoContext` + `build_context` (default-branch heuristic,
  `thin` flag, non-default-branch compare to bound API cost, README screenshot
  discovery via `first_readme_image`).
- `docsgen/llm_client.py` — provider-agnostic seam (DashScope + Anthropic on
  `requests`, zero new deps); `LLMError` wraps all call failures; `get_client`
  reads env.
- `docsgen/record_gen.py` — prompt + `generate_record` (validate→retry→
  `RecordGenerationError`); `_assemble` merges LLM-owned vs generator-owned fields
  with an import-time disjoint assert (trust boundary); non-dict LLM JSON handled.
- `docsgen/render.py` — pure-Python HTML page (JSON island + JSON-LD + 2 Mermaid
  diagrams + screenshot/quickstart/features + hygiene panel); XSS-hardened
  (`</`→`<\/` in script blocks, `<`→`&lt;` in Mermaid, http(s)-only img src).
- `docsgen/aggregate.py` — records → `web/data/projects.json`.
- `docsgen/generate.py` + `cli.py gen-docs` + Makefile `gen-docs` + `.env.example`.

Human-facing additions (per mid-session request): UI screenshot (generator-derived
from README), quickstart + features overview (LLM-authored).

NOT done (user-gated): Task 10 guinea-pig live generation of
`generate_title_headline_hooks` + deploy to davidbmar.com — blocked on a live
`DASHSCOPE_API_KEY` in `.env` and deploy authorization. Task 11 (GitHub Action) —
optional, not built.

## Decisions Made

- Work directly on `main` (user choice) — no worktree.
- Template-renders-structured-data over AI-writes-raw-HTML (locked in spec; user
  confirmed by proceeding).
- Zero new dependencies: `requests` for GitHub + LLM HTTP, stdlib for validation +
  HTML rendering.
- Tests run through `.venv/bin/python` (system python3 lacks fastapi/etc.).
